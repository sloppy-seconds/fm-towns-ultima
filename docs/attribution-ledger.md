# The attribution ledger

Plan items [0c](plan-attribution.md) and [0d](plan-attribution.md). One row per function, ten columns,
committed as `docs/ledger.json`, generated by `tools/ledger.py`. Both build tracks read it and neither may
write a state it has not earned.

The honest headline: of **875 functions, 823 are `unattributed`**. That is not a to-do list and it is not a
failure. It is what is actually known, and the whole point of the ledger is that the number is visible instead
of being papered over with confident-sounding adjectives.

## What is in it

| count | value |
|---|---|
| population | 875 functions, the whole game module |
| `compiler-1.73-matched` | 11, of which **9 `proven`** (byte-identical through the authentic driver) and **2 `probable`** (framed, blocked on a toggle) |
| `hand-asm-positive` | 41, all `probable` |
| `unattributed` / `unknown` | 823 |
| size asserted | 451, from `docs/corpus.json` |
| size `n-a` | 424, because no census entry asserts an extent |

## The frames, which is the one way this could have gone silently wrong

`module/` names its functions `f_000e9c2c`. `docs/corpus.json`, `docs/routines.json` and every page in this
repository use `0xe9e2c`. **Those are different frames, 0x200 apart**, because the port recompiles a copy
stripped of the MP header while the documents quote file offsets.

The first version of `tools/ledger.py` compared them directly and produced a ledger that looked merely
sparse: 11 asserted sizes out of 454, and none of the ten matched routines mapped at all. Both symptoms read
like missing data rather than a units error, which is what makes this worth writing down.

Measured after the shift:

| | |
|---|---|
| census addresses landing on a module function after `-0x200` | **all but 23 of them**. The census total is owned by [call-graph.md](call-graph.md), so it is not restated here |
| the 23 that do not | the zero-fill seeds `cfgwalk` refuses by design (`0x17309`, `0x9829b`, `0x9b26b` among them) |
| sized census entries landing on a module function | **451 of 454** |

Applying the shift took asserted sizes from 11 to 451 and matched routines from 0 to 10 at the time. Promoting
`0xe140c` under item 4f made it eleven.

The ledger reports **file** offsets, as the schema says, and converts the module addresses on the way in. The
conversion is one constant, `FILE_FRAME_DELTA = 0x200`, and the file records its own frame in `addr_frame` so
a reader does not have to know.

## How each column is earned

| column | rule |
|---|---|
| `addr` | file offset. See above |
| `size` | from `docs/corpus.json`, an asserted derivation. Where there is no entry the value is `n-a`, **not** the gap to the next function start, because item 12a says an inferred extent gets no verdict |
| `module` | `ENCHANT` for all of these. TBIOS is a different binary and is deferred |
| `attribution` | `compiler-1.73-matched` only for routines `docs/routines.json` classes `matched`. `hand-asm-positive` only where the atlas census supplies positive exclusion evidence. `unattributed` otherwise |
| `confidence` | `proven` only for a byte-identical driver verification. `probable` where the evidence is one signal. `unknown` is the default and is written out rather than left blank |
| `cluster` | the feature-vector group from `tools/cluster.py`, so the two cannot disagree |
| `recomp` | `compiled`, because presence in `module/` *is* the recompiler's output |
| `port-coverage` | `n-a` for every row |
| `indirect` | `n-a` for every row |
| `notes` | the evidence line, or `n-a`. A blank is rejected by the gate |

**The two `n-a` columns are a statement, not an omission.** No tool reports per-function port coverage yet
(item 11a is the one that would produce it) and no tool locates the 30 unresolved indirect transfers per
function, only counts them. Both are named in the ledger's own `unpopulated` field with the reason, because an
empty column that nobody explains is indistinguishable from one that was forgotten.

## What it deliberately does not do

**It does not promote `base-fold` to a match.** `docs/routines.json` puts 21 routines in that class, and the
class is mixed: `0xfdeb6` is a two-instruction global getter that recovers cleanly under the disp32 standard,
while `0xf3e24` is recorded as "24 of 25 bytes match". Parsing those prose entries to decide which ones
counted would be guessing from wording, which is the failure mode `plancheck` already has a scar from. So
base-fold rows stay `unattributed` and carry `class=base-fold` plus the existing description in `notes`. A
human can promote them. The tool will not invent the distinction.

**It does not claim the 41 xor functions are proven hand-written.** They are `probable` on one signal, from one
instrument, against an atlas that was wrong about three other claims in the same session. The note says so in
those words.

## The gate

`tools/checkall.js` asserts, and each assertion was written to be able to fail:

- the population matches the row count and covers the whole module
- every row carries every column, populated or an explicit `n-a`
- every row's cluster exists, and cluster sizes sum to the population
- **no `proven` or `probable` row without an evidence line**, where `n-a` does not count as evidence
- **no `hand-asm-positive` row whose notes quote no idiom in backticks**, because a hand-asm label without the
  idiom that excludes compiler output is exactly the laundering item 12a exists to stop
- `summary.unattributed` equals the real count, so the number cannot be quietly restated
- `tools/ledger.py --check` reproduces the committed file byte for byte

This check found a real defect on its first run: 738 rows had an empty `notes` rather than `n-a`, so the gate
was doing its job before the ledger was ever cited.

## Reproducing

```
./tools/ledger.py            # write docs/ledger.json, print the summary
./tools/ledger.py --check    # compare against the committed file
./tools/ledger.py --json     # the summary only
```

`tools/cluster.py --write` was retired at the same time. It wrote `docs/ledger.json` with only the cluster
column, and two writers of one ledger silently drop each other's columns. It now refuses and points here.
